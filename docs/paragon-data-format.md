# paragon-data.json Format Reference

This file is the paragon game-data database used by `D4LootBench.Paragon`: board layouts, node
definitions, glyphs, glyph affixes, and rare-node bonus thresholds. It follows the same conventions
as `d4-data.json` (see `docs/d4-data-format.md`): the file is embedded in the library, a local copy
next to the `.exe` overrides it, and all `snoId` fields are `"0x"`-prefixed hex SNO IDs.

## Provenance and Regeneration

Generated by `tools/extract-paragon-data.cs` from a [DiabloTools/d4data](https://github.com/DiabloTools/d4data)
checkout (the parsed CASC dump the community maintains per patch). d4data is ~10 GB, but the
extractor only needs the paragon slices — a blob-filtered sparse checkout is enough:

```bash
git clone --filter=blob:none --depth 1 --no-checkout https://github.com/DiabloTools/d4data.git
cd d4data
git sparse-checkout set --no-cone \
    '/json/base/meta/ParagonBoard/*' '/json/base/meta/ParagonNode/*' \
    '/json/base/meta/ParagonGlyph/*' '/json/base/meta/ParagonGlyphAffix/*' \
    '/json/base/meta/ParagonThreshold/*' \
    '/json/base/meta/GameBalance/AttributeFormulas.gam.json' \
    '/json/enUS_Text/meta/StringList/ParagonBoard_*' \
    '/json/enUS_Text/meta/StringList/ParagonNode_*' \
    '/json/enUS_Text/meta/StringList/ParagonGlyph_*' \
    '/json/enUS_Text/meta/StringList/Power_Paragon_*'     '/json/base/meta/Power/Paragon_*' '/json/base/meta/Power/ParagonGlyph_*'
git checkout HEAD
# (In Git Bash, write .git/info/sparse-checkout directly — MSYS path mangling corrupts
#  leading-slash patterns passed on the command line.)
```

Then:

```powershell
dotnet run tools/extract-paragon-data.cs -- --d4data <path-to-d4data> --out src/D4LootBench.Paragon/Data/paragon-data.json
```

## The Multiplier Calibration (important caveat)

Node magnitudes in the game files are formulas like `"3 * ParagonPowerBudgetMultiplierNodeMagicOffensive()"`.
The six `ParagonPowerBudgetMultiplierNode{Magic,RareMinor,RareMajor}{Offensive,Defensive}` functions
are **engine built-ins that do not appear anywhere in the data dump**. Their constants are hardcoded
in the extractor, calibrated empirically against displayed in-game values (Season 14 / patch 3.1.x). The 3.2.1 regeneration changed no existing node FORMULAS beyond three redesigned nodes, but that can't confirm the constants themselves (they're applied identically every run) — re-validated in-game at 3.2.1 (2026-09-24, Warlock magic nodes outside any glyph radius): Damage to Vulnerable `2.5 * f()` = 6.25% displays **6%**, Damage `2 * f()` = 5% displays **5%**, Critical Strike Damage `3 * f()` = 7.5% displays **8%** — consistent with MagicOffensive 0.025 and the game ROUNDING tooltip percents to whole numbers (a changed constant, 8/3 ≈ 0.0267, would have shown 7% and 5.3%). The planner keeps the exact fractions. The new Superiority glyph's scalar 300 does match its patch-note +30% under the ÷10 node-buff rule:

| Function | Value | Anchor |
|---|---|---|
| MagicOffensive | 0.025 | magic crit-damage node = `3 * f()` displays 7.5% |
| MagicDefensive | 0.02 | magic max-life node = `1 * f()` displays 2.0% |
| RareMinor/RareMajorOffensive | 0.05 | rare crit-damage node = `3 * f()` displays 15% |
| RareMinor/RareMajorDefensive | 0.04 | rare max-life node = `1 * f()` displays 4.0% |
| GlyphThresholdBonusRare (power tuning) | 0.1 | 3.2.1 patch notes: Superiority `1 * f()` = +10% DR, Talon `2.5 * f()` = 25%; Exploit `3 * 10 * f()` = 3 s Vulnerable |
| NodeLegendary (power tuning) | 0.15 | designers write these pre-divided: Lust for Carnage `(2 / 0.15) * f()` Spirit, Enchantment Master `(.3 / .15) * f()` potency |

Values are fractions (`0.05` = 5%) for percent attributes; flat-stat formulas (core stats, max
resource) embed their own scaling and produce flat numbers. The full extraction was validated
against Wowhead's live paragon-calc dataset: the Sorcerer starter board matched 26/26 stat values
and Burning Instinct matched 201/201, with identical cell geometry on both. **If Blizzard rebalances
paragon budgets, re-validate these constants**, not just the extraction.

The emitted `multipliers` object records the constants used, and every node attribute keeps its
`formula` text so values can be recomputed if a constant changes.

## Top-Level Structure

```json
{
  "formatVersion": 1,
  "source": "DiabloTools/d4data (<commit>)",
  "notes": "…",
  "multipliers": { "ParagonPowerBudgetMultiplierNodeMagicOffensive": 0.025, … },
  "boards":     [ … ],
  "nodes":      [ … ],
  "glyphs":     [ … ],
  "thresholds": [ … ]
}
```

Current counts (patch 3.2.1.73552): 80 boards, 566 nodes, 161 glyphs, 52 thresholds.

## boards

```json
{
  "snoId": "0x000e56fd",
  "internalName": "Paragon_Sorc_03",
  "name": "Static Surge",
  "className": "Sorcerer",
  "boardIndex": 3,
  "width": 21,
  "contentLicense": 0,
  "nodes": [ { "x": 10, "y": 0, "node": "0x000f2c21" }, … ]
}
```

- Boards are sparse 21×21 grids; `x` is the column (0-based, left→right), `y` the row (top→bottom),
  exactly matching the in-game orientation before any player rotation.
- `node` references a `nodes[]` entry by `snoId`; the same node definition appears on many boards.
- `boardIndex 0` is the class starting board. `contentLicense != 0` marks expansion-gated boards.
- Every class has 9–10 boards; `className` is one of the 8 class names used in `d4-data.json`.

## nodes

```json
{
  "snoId": "0x000a3de0",
  "internalName": "Barbarian_Rare_001",
  "name": "Iron Strength",
  "kind": "Rare",
  "attributes": [
    {
      "attribute": "Resource_Max_Bonus",
      "param": 1,
      "formulaName": "ParagonNodeResourceBonus_RareMajorGlyph",
      "formula": ".4 * 100 * ParagonPowerBudgetMultiplierNodeRareMinorOffensive()",
      "value": 2,
      "isThresholdBonus": true
    },
    { "attribute": "Strength_Core", "formula": "10", "value": 10, "isThresholdBonus": false }
  ],
  "thresholds": [ "0x000f7d8e" ],
  "tags": [ "Elite", "Strength", "Damage" ]
}
```

- `kind`: `Normal`, `Magic`, `Rare`, `Legendary`, `GlyphSocket`, `Gate`, `Start` (derived from
  `eRarityOverride` 0/2/3/4 plus the gate/socket/start flags).
- `name` is null for generic magic nodes — the game titles those from their attribute at runtime.
- `attribute` names are the engine's attribute enum names (`Crit_Damage_Percent`, `Strength_Core`, …);
  `param` disambiguates parameterized attributes (damage type, resource type) and is null when unused.
- `value` is the resolved magnitude (fraction for percent attributes, flat otherwise); null only if
  the formula referenced something unknown (currently none do).
- `isThresholdBonus: true` marks attributes granted only when the node's threshold requirement is met.
- Legendary nodes carry `power` instead of meaningful attributes (glyph affixes carry the same
  shape as `bonusPower` — the glyph's Additional Bonus):
  `{ "snoId", "name": "Paragon_Sorc_Legendary_001", "description", "values", "multiplierPercents" }`.
  `values` are the power's script formulas SF_0..SF_n from `Power/<name>.pow.json`, evaluated
  (constants, SF cross-references, the calibrated built-ins, `Min`/`Max`, equal-branch ternaries);
  null where a value depends on live character attributes. `description` is the `desc` string-list
  template rendered with those values — `[expr|format|]` tokens where the format flags are `x`
  (multiplicative, rendered `[x]`), `%`, `+` (sign) and a digit (decimals), several `|…|` segments
  union; bare `{SF_n}` prints the value; markup is stripped; unresolvable values print `?` (only
  live-character values such as "Current Bonus" or Maximum Life — 8 of 73 legendaries, 3 glyph
  bonuses at 3.2.1). `multiplierPercents` lists every `[x]` value in tooltip order; the first is
  the node's headline multiplier (`LegendaryNodeInfo`).
- There is no cost field. Every node costs 1 paragon point, with one engine-side exception
  (user-verified vs a live build, July 2026): a board crossing's Attachment Gate PAIR costs one
  point total — buying your side's gate attaches the board and auto-purchases the far gate,
  which also does not grant its +5 attributes. Modeled by `Solver/GateCrossings`.

## glyphs

```json
{
  "snoId": "0x000f9c50",
  "internalName": "Rare_001_Intelligence_Main",
  "name": "Enchanter",
  "rarity": 1,
  "classes": [ "Sorcerer" ],
  "affixes": [ … ]
}
```

Glyph `affixes` (from `ParagonGlyphAffix`) carry the scaling model:

- `attributeMaps` — source→destination attribute pairs (e.g. Intelligence in radius → all damage).
- `startingBonusScalar` + `addedBonusScalarPerLevel` — bonus magnitude at level 1 and per level.
- `affectedNodeRarity` / `requiredRarity` / `bonusOperation` — raw enum ints from the game files.
- The legendary-upgrade affix (`*_Legendary` internal names) applies once the glyph is upgraded.

Class order for the underlying game-file flag arrays is
`[Sorcerer, Druid, Barbarian, Rogue, Necromancer, Spiritborn, Paladin, Warlock]`, derived from
single-class glyph names; the extractor emits resolved class-name arrays, so consumers never see
flag indices. Glyph radius/level breakpoints are not in the data files (engine-side); model them
in code if needed.

## thresholds

Rare-node bonus requirements. The requirement scales with the 0-based order the board was attached in:

```json
{
  "snoId": "0x000f7d8e",
  "internalName": "WillPowerSide1",
  "classes": [ "Sorcerer", "Barbarian", "Necromancer", "Paladin" ],
  "requirements": [
    {
      "attribute": "Willpower_Total",
      "formula": "190 + (75 * ParagonBoardEquipIndex)",
      "valuesByBoardIndex": [ 190, 265, 340, 415, 490, 565 ]
    }
  ]
}
```
